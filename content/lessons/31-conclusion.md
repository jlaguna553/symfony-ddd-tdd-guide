El objetivo de esta guía no es terminar con:

> "Ya hice un CRUD en Symfony."

Sino poder llegar a:

> "Construí un módulo User siguiendo DDD, manteniendo el dominio independiente de Symfony y Doctrine. Separé Commands y Queries, utilicé Repository Ports y Adapters, probé el dominio y los casos de uso sin infraestructura, y después validé Doctrine y MySQL mediante Integration Tests sobre una base de datos exclusiva para testing. Finalmente probé el contrato HTTP mediante Functional Tests y centralicé el manejo de errores."

Ese cambio de explicación es enorme. Porque ya no estás hablando solamente de cómo hacer que el código funcione. Estás hablando de:

- cómo diseñarlo
- cómo aislarlo
- cómo probarlo
- cómo evolucionarlo
- cómo proteger sus límites
- cómo desplegarlo
- y cómo detectar cuando alguien rompe la arquitectura

Y esa es justamente la parte que convierte un CRUD de Symfony en un ejercicio bastante más cercano a lo que se espera de un **Senior/Tech Lead**.

Si llegaste hasta aquí lección por lección, ya tienes el proyecto completo construido y, más importante todavía, la narrativa para defenderlo. Vuelve a las [preguntas de entrevista](/lecciones/preguntas-de-entrevista) cuantas veces necesites antes de tu próxima conversación técnica.
